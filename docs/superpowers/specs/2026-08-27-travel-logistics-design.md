# 出行与住宿模块设计

## 目标

为单目的地行程提供可解释的城际交通、市内交通与全程单一住宿据点，并使预算分类与页面展示一致。

## 范围

本期仅支持一个目的地、全程一个住宿区域和可选返程。交通与住宿均是规则估算，不接入票务、酒店或实时路线服务。

## 数据结构

状态新增 `travel_logistics`：

- `origin`、`destination`、`include_return`；
- `intercity_legs`：去程或返程的起点、终点、方式、估算距离、时长、费用及 `estimated|pending` 状态；
- `accommodation`：区域、档次、入住/离店日期、晚数、房间数、每晚价格、总价和 `estimated` 状态；
- `local_transport_legs`：按天保存的景点间交通段，含起终点、方式、估算距离、时长与费用。

`budget.detail` 固定包含 `intercity_transport`、`local_transport`、`hotel`、`food`、`tickets`。`pending` 的城际段为零元，明确不计入总预算。

## 计算规则

未提供出发地时产生一条 `pending` 去程段，不估算费用。提供出发地时，以城市间直线距离乘交通方式费率估算；默认方式为高铁。若选择返程，生成目的地到出发地的对称返程段。住宿晚数为 `max(1, duration - 1)`，每晚价格继续沿用经济/中档/高端的 200/450/1000 元，超过两人按人数除以二计算房间系数。

市内交通由既有相邻景点坐标距离计算，转换为独立段；预算不再从行程项中隐式读取交通费。

## UI

结构化表单新增出发城市与“包含返程”。行程右栏新增交通与住宿卡片：先展示全程住宿，再展示城际去返程，最后按天展示市内交通。每日行程卡显示地址、提示与上一站到本站的交通信息。预算卡显示五个细分分类。

## 验收

1. 未填出发地时，城际交通显示待补充且预算为零。
2. 有出发地且包含返程时，预算有去返程城际费用。
3. 住宿只生成一个全程对象，费用与预算 `hotel` 一致。
4. 页面能展示城际、市内交通和住宿，且五项预算明细相加等于总额。
