# 实时市内路线与方案确认设计

## 目标

将市内交通段升级为高德路线结果，并允许用户确认规则估算的城际交通和全程住宿方案。

## 范围与约束

- 仅市内交通调用已配置的高德地图 API；不接入酒店、机票或火车票服务。
- 城际交通和住宿继续是规则估算，不能显示为实时价格。
- 高德不可用、无坐标或无路线时，回退现有费率估算，行程生成不得失败。
- 已确认的城际/住宿条目在后续重规划时保留，除非用户主动修改交通或住宿偏好。

## 数据模型

每个 `local_transport_leg` 增加 `distance_km`、`duration_minutes`、`estimate_source`（`amap` 或 `rule`）和 `status`（`estimated`）。城际段和住宿新增相同的 `estimate_source: rule`，并支持 `status: estimated|confirmed|pending`。

状态新增 `logistics_confirmations`，按 `intercity:<kind>` 与 `accommodation` 存储确认后的不可变物流项。生成新物流结构时优先恢复这些条目。

## 流程

1. 行程项已有坐标时，物流服务调用高德驾车距离接口，写入距离和根据用户偏好推导的时长/费用。
2. 调用失败时，保留原有的 `leg_transport_cost` 与 `rule` 来源。
3. 前端对城际段和住宿提供确认按钮，调用新接口存储确认条目，刷新当前会话物流结构。
4. 后端返回的预算继续使用已确认条目的价格；确认动作不改变费用，只锁定其方案和展示状态。

## 验收

1. 高德可用时，市内交通段显示真实距离、时长和 `amap` 来源。
2. 高德失败时，生成不失败，市内段保持 `rule` 来源。
3. 用户确认住宿或一条城际段后，刷新/重规划仍显示“已确认”。
4. 城际/住宿始终显示“规则估算”，除非未来接入对应报价服务。
