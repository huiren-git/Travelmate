核验结论（基于实际代码）：
- 前端 `StructuredPreferences`（frontend/src/types/chat.ts:14-23）**无 start_date 字段**，用户无法指定出发日期。
- `parse_structured_preferences`（preferences_parser.py）只产出 budget_level/pace/travelers/.../interests，不产出 start_date。
- `chat.py:138` `start_date = structured_values.get('start_date')` → **永远 None**（`_structured_state_values` 只回 `{"structured_preferences": parsed}`）。
- `get_start_date`（state_utils.py:62）缺失时回退硬编码 `DEFAULT_START_DATE = date(2026,8,10)`（state_utils.py:10）——**写死、随时间必然过期**，非"对话当天"。第一天日期实为 2026-08-10。
- 起始时刻：`_normalize_item`（itinerary_agent.py:772）兜底 `time='09:00'`，system_prompt schema 示例（L610）也是 `09:00`。
- `_apply_time_based_status`（L826）只是事后把早于 current_time 的 upcoming 标 completed，非事前规避。
- 现象链路（show_widget 图）：前端 current_time=对话时刻 / 无 start_date → chat.py start_date=None → get_start_date 回退 2026-08-10 → 第一天 2026-08-10 09:00 < current_time(10:00) → 标 completed。

拟定方案（3 层，用户自落）：
1. 必改(根因A)：`get_start_date` 缺失回退改为 `date.today()+timedelta(days=1)`（明天），弃用静态 DEFAULT_START_DATE 常量。
2. 必改(可指定)：扩 `StructuredPreferences` 加 `start_date?: string`（ISO 日期）+ `preferences_parser` 透传该键，复用 chat.py:138 现有链路；可选再加 `start_time?`。语义：提供则用，未提供走方案1的"明天"。
3. 增强(根因B+事前规避)：当用户指定"今天出发"且 current_time 已过 9:00，在 `_state_payload` 注入"第一天建议起始时刻"（=max(09:00, current_time 取整)），prompt 加规则"首日首个活动不得早于该时刻；当天剩余不足半日则顺延次日"。可不改 normalize 兜底（09:00 仅示例）。

风险/待决策：方案1跨午夜边界多次调用 date.today() 理论不一致（实际可忽略）；方案2"明天"基准日 vs 用户指定日期的优先级；方案3增加 prompt 复杂度与重试概率。需用户确认落地方案范围后再改代码。

## TripTipsCard 宽度/对齐修复（多轮样式调试，tsc 通过）
目标：贴士卡宽度固定=气泡最大宽(80% 列宽)、且左缘与气泡对齐(x=48)。最终落地：`<Card className="!ml-12 !w-[80%] ...">` 直接做 980 列子元素（删外层 div 包裹），tsc 零报错。
- 关键坑1（antd 吃 margin）：antd `.ant-card` CSS 在 Tailwind 之后加载，`margin-left` 被归零；必须 `!ml-12`(`margin-left:3rem !important`) 才压得过。同理 width 也用 `!w-[80%]`。
- 关键坑2（百分比参照系被中间层偷换）：一度用 `<div className="flex ml-12"><Card className="!w-[80%]">` 包裹，导致 Card 的 80% 相对的是「被 ml-12 推过 48px、又 stretch 拉满的 div(=列宽-48)」而非整列 → 卡片≈0.8×932=745px，气泡=0.8×980=784px，差 ~39px。教训：要让子元素的 `X%` 与另一元素同基准，二者必须直接是同一容器的子元素，中间不能插任何会缩窄可用宽度的包裹层。
- 气泡宽度源：`ChatMessages.tsx` 消息行 `flex gap-3`，avatar 36+gap12=48px 偏移，气泡 `max-w-[80%]` 相对行宽(=列宽)。贴士卡与之对齐须 48px 偏移 + 80% 宽同基准。
- 取舍：`!w-[80%]` 是写死 80%，仅当气泡也满 80%（AI 回复长文折行）时等长；短回复气泡<80% 会比卡片窄，属「写死宽度」固有代价，用户已知情接受。
