  - 生成 summary_text 后同时 `update["messages"] = [AIMessage(content=summary_text)]`，借助 `add_messages` reducer 累加。
  - supervisor 的 `__end__` 追问路径本就返回 AIMessage，无需改；itinerary/budget 不产用户文本，无需改。

## 修复 /profile/* 打不开（崩溃根因 + 两处修复）
- 现象：进 `/profile/*`（含 preferences）加载一会儿后白屏打不开。
- 根因：动态历史数据让 `getProfileTravelStats`→`getInclusiveDays` 崩溃。`frontend/src/utils/profileStats.ts` 的 `parseDate/getInclusiveDays` 假设 `dateRange` 永远为 `YYYY.MM.DD - YYYY.MM.DD` 三段式；旧静态 mock 恒满足，但动态数据会出现 `'日期待定'`（会话无 start_date 时 `listDateRange` 返回）或 `'8.17 - 8.19'` 两段式。`'日期待定'.split(' - ')` → endDate=undefined → `parseDate(undefined)` → `undefined.split('.')` 抛 TypeError。而 `useProfilePageData` 在**任意** profile 子路由都跑 `fetchSessions` effect，`setHistories` 触发共享父 `ProfileLayout`（`ProfileInfoCard` 用 `profileStats`）重渲染 → 未捕获异常整页崩溃。
- 修复 1：`frontend/src/utils/profileStats.ts` 重写 `parseDate`（兼容 `YYYY.MM.DD`、`M.D` 按当前年补全、非法/缺值返回 null）、`getInclusiveDays`（`'日期待定'`/空值/缺段返回 0）。
- 修复 2：`frontend/src/hooks/useProfilePageData.ts` 历史 effect 加门控——`useLocation()`+`getProfileOutletFromPathname` 算 `activeOutlet`，仅 `activeOutlet==='history'` 时执行；依赖改为 `[activeOutlet]`。避免进 preferences/settings 也拉历史（节省请求，也消除崩溃诱因）。
- 注意：门控后 preferences/settings 子路由 `histories=[]` → `profileStats` 显示 0 次/0 城/0 天，属预期取舍（用户明确要限定）。
- 验证：`npx tsc -b` 通过（exit 0）。
