## REPLAN 链路根因分析（只分析，未改代码）
- **根因 1（时区）**：`itinerary_agent._parse_current_datetime` 对 `2026-08-21T05:48:27.960Z`（前端 `new Date().toISOString()`）做 `.replace(tzinfo=None)`，把 UTC 抹成 naive `05:48`；而行程项时间是中国本地墙钟（naive `14:00`）。结果 `_is_locked_item` 全返回 False → `locked_items: []` → 整段行程进 `editable_itinerary` → LLM 全量重写（表现为"重新生成行程"）。修法：`if parsed.tzinfo is not None: parsed = parsed.astimezone(timezone(timedelta(hours=8))).replace(tzinfo=None)`。
- **根因 2（用户原话从未进 prompt，比时区更致命）**：`_state_payload` 的 key 里**没有 user_message**；`_build_itinerary_messages` 的 HumanMessage 只有这个 payload 的 JSON。replan 时 LLM 完全看不到"把万绿园换成有空调的景点"。唯一侧信道是 `_store_user_memory_candidates` 先写记忆、随后 `_retrieve_relevant_preferences` 相似度回捞（极不可靠），以及仅在 interrupt/resume 路径才有值的 `user_decision.hint`。修法：payload 加 `user_instruction`。
- **replan 作用域设计要点**：`_replan_payload` 与 `_merge_replan_itinerary` 共用同一个 `_is_locked_item` 谓词——只要把"作用域外的未来项"也判定为 locked，两处会同时生效（LLM 看不到 + merge 原样回填原 item，保留 image_url/cost 等全字段）。作用域三层：item（活动名子串≥3字命中）→ day（相对日/第N天/M月D日；用"行程/安排/计划"等标记词区分"明天的行程"是目标而"今天太累了"是原因）→ all（兜底=现有行为）。
- **注意 LangGraph 硬约束**：新增 `replan_scope` / `replan_changes` 等 update key 必须先在 `TravelAgentState` 声明，否则 `InvalidUpdateError`。
- **validator 分叉**：`is_finished` 分支目前无条件调 `_generate_summary_text`（行程总结语）。replan 应改为按 `get_plan_mode` 分叉，用 old(`get_daily_itinerary(state)`) vs new(`get_draft_daily_itinerary(state)`) 的 diff 生成"指令反馈语"。字段沿用 `summary_text`（前端 `useChatPageState.extractDoneItineraryContent` 已优先读它，零前端改动）；后端 `summary_text` 仅 validator/state/chat.py 初始化三处引用，无其他消费方。
