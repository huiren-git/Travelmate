# 数据库表说明

本文档根据当前代码配置与 `data` 目录下现有数据库文件整理，覆盖 TravelMate 后端目前实际使用的持久化结构。

## 数据库文件

| 文件 | 来源 | 用途 |
| --- | --- | --- |
| `data/checkpoint.db` | LangGraph SQLite checkpointer | 保存对话/行程规划工作流的 checkpoint 与节点写入记录 |
| `data/chroma.sqlite3` | ChromaDB PersistentClient | 保存向量库集合、文档、metadata、全文检索与迁移信息 |
| `data/checkpoint.db-shm` | SQLite WAL 辅助文件 | SQLite 共享内存文件，运行期自动生成 |
| `data/checkpoint.db-wal` | SQLite WAL 辅助文件 | SQLite 预写日志文件，运行期自动生成 |

配置来源：

- `settings.database_path`：默认 `./data/checkpoint.db`
- `settings.chroma_persist_dir`：默认 `./data`
- `settings.chroma_collection_prefs`：`user_preferences`
- `settings.chroma_collection_actions`：`user_actions`

## 1. LangGraph Checkpoint 数据库

数据库文件：`data/checkpoint.db`

该库由 `langgraph-checkpoint-sqlite` 管理，业务代码不直接维护 DDL。它用于恢复会话状态、枚举历史会话、软删除会话，以及支持中断/恢复流程。

### 1.1 `checkpoints`

保存每次图执行产生的 checkpoint 快照。

| 字段 | 类型 | 是否必填 | 主键序号 | 说明 |
| --- | --- | --- | --- | --- |
| `thread_id` | `TEXT` | 是 | 1 | LangGraph 会话 ID，对应 API 中的 `thread_id` / `session_id` |
| `checkpoint_ns` | `TEXT` | 是，默认 `''` | 2 | checkpoint 命名空间 |
| `checkpoint_id` | `TEXT` | 是 | 3 | checkpoint 唯一 ID |
| `parent_checkpoint_id` | `TEXT` | 否 | 否 | 父 checkpoint ID，用于串联状态历史 |
| `type` | `TEXT` | 否 | 否 | 序列化类型 |
| `checkpoint` | `BLOB` | 否 | 否 | checkpoint 主体，包含图状态快照 |
| `metadata` | `BLOB` | 否 | 否 | checkpoint 元数据 |

主键：`(thread_id, checkpoint_ns, checkpoint_id)`

业务上 checkpoint 中主要保存 `TravelAgentState`，包括：

| State 字段 | 说明 |
| --- | --- |
| `messages` | 对话消息历史 |
| `user_id` | 用户标识 |
| `thread_id` | 会话标识 |
| `destination` / `origin` | 目的地、出发地 |
| `start_date` / `duration` | 出发日期、旅行天数 |
| `structured_preferences` | 结构化旅行偏好 |
| `weather_info` | pre_fetcher 获取的天气信息 |
| `fetched_attractions` | pre_fetcher 获取的景点列表 |
| `daily_itinerary` | 已通过校验的正式行程 |
| `budget` | 已通过校验的预算 |
| `draft_daily_itinerary` / `draft_budget` | 待校验草稿 |
| `plan_mode` / `current_mode` | 当前规划模式 |
| `current_time` | 动态修改时的时间锚点 |
| `validation_attempts` / `hard_validation_attempts` / `soft_validation_attempts` | 校验重试计数 |
| `validation_report` | 校验报告 |
| `is_finished` | 工作流是否完成 |
| `deleted_at` | 会话逻辑删除时间 |
| `next_node` | Supervisor 路由结果 |

### 1.2 `writes`

保存图执行过程中各节点写入 channel 的中间记录。

| 字段 | 类型 | 是否必填 | 主键序号 | 说明 |
| --- | --- | --- | --- | --- |
| `thread_id` | `TEXT` | 是 | 1 | LangGraph 会话 ID |
| `checkpoint_ns` | `TEXT` | 是，默认 `''` | 2 | checkpoint 命名空间 |
| `checkpoint_id` | `TEXT` | 是 | 3 | 所属 checkpoint ID |
| `task_id` | `TEXT` | 是 | 4 | 节点任务 ID |
| `idx` | `INTEGER` | 是 | 5 | 同一任务内写入顺序 |
| `channel` | `TEXT` | 是 | 否 | 写入的状态 channel |
| `type` | `TEXT` | 否 | 否 | 序列化类型 |
| `value` | `BLOB` | 否 | 否 | 写入值 |

主键：`(thread_id, checkpoint_ns, checkpoint_id, task_id, idx)`

## 2. ChromaDB 向量数据库

数据库文件：`data/chroma.sqlite3`

该库由 ChromaDB 管理。当前代码初始化两个业务集合：

| 集合名 | 配置项 | 用途 |
| --- | --- | --- |
| `user_preferences` | `settings.chroma_collection_prefs` | 用户旅行偏好记忆 |
| `user_actions` | `settings.chroma_collection_actions` | 用户操作日志与历史决策记忆 |

当前库中已存在这两个集合，但尚未写入 embedding metadata 样本。

### 2.1 核心业务写入结构

业务代码通过 `src/services/memory_manager.py` 写入 Chroma。每条记忆包含：

| 逻辑字段 | 存放位置 | 说明 |
| --- | --- | --- |
| `memory_id` | Chroma document id 与 metadata | 形如 `mem_<12位随机串>` |
| `text` | Chroma document content | 可检索文本 |
| `user_id` | metadata | 用户隔离字段，检索时按该字段过滤 |
| `memory_type` | metadata | `preference` 或 `action` |

偏好记忆常见 metadata：

| 字段 | 说明 |
| --- | --- |
| `preference_id` | 用户偏好标签 ID，形如 `pref_<随机串>` |
| `category` | 偏好类别：`diet`、`pace`、`budget`、`interest`、`accommodation`、`transport` |
| `source` | 来源：`manual` 或 `inferred` |
| `confidence` | 置信度，0 到 1 |
| `is_active` | 是否生效 |
| `created_at` / `updated_at` / `deleted_at` | 时间戳 |

操作日志常见 metadata：

| 字段 | 说明 |
| --- | --- |
| `thread_id` | 所属会话 ID |
| `action_type` | 操作类型，如 `delete`、`replace`、`add`、`pace_change`、`confirm`、`replan` |
| `timestamp` | 操作发生时间 |
| `inferred_preference` | 从操作中推断出的用户偏好 |
| `source` | 来源，如 `chat_resume`、`itinerary_agent` |
| `decision_action` | 用户恢复流程中的决策动作 |

### 2.2 `collections`

Chroma 集合定义表。

| 字段 | 类型 | 是否必填 | 主键 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `TEXT` | 否 | 是 | 集合 ID |
| `name` | `TEXT` | 是 | 否 | 集合名称，如 `user_preferences` |
| `dimension` | `INTEGER` | 否 | 否 | 向量维度，可能在首次写入后确定 |
| `database_id` | `TEXT` | 是 | 否 | 所属 database ID |
| `config_json_str` | `TEXT` | 否 | 否 | 集合配置 JSON |
| `schema_str` | `TEXT` | 否 | 否 | 集合 schema |

外键：`database_id -> databases.id`

### 2.3 `embeddings`

Chroma 文档/向量条目索引表。

| 字段 | 类型 | 是否必填 | 主键 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `INTEGER` | 否 | 是 | 内部自增 ID |
| `segment_id` | `TEXT` | 是 | 否 | 所属 segment |
| `embedding_id` | `TEXT` | 是 | 否 | 业务传入的文档 ID，如 `mem_xxx` |
| `seq_id` | `BLOB` | 是 | 否 | Chroma 内部序列 ID |
| `created_at` | `TIMESTAMP` | 是，默认 `CURRENT_TIMESTAMP` | 否 | 创建时间 |

唯一索引：`embedding_id`

### 2.4 `embedding_metadata`

保存单值 metadata。

| 字段 | 类型 | 是否必填 | 主键序号 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `INTEGER` | 否 | 1 | 对应 `embeddings.id` |
| `key` | `TEXT` | 是 | 2 | metadata 键 |
| `string_value` | `TEXT` | 否 | 否 | 字符串值 |
| `int_value` | `INTEGER` | 否 | 否 | 整数值 |
| `float_value` | `REAL` | 否 | 否 | 浮点值 |
| `bool_value` | `INTEGER` | 否 | 否 | 布尔值 |

外键：`id -> embeddings.id`

## 3. Redis 缓存键

Redis 不属于关系型数据库表，但当前项目也使用它缓存外部 API 结果。

| Key 模式 | 写入位置 | TTL | 内容 |
| --- | --- | --- | --- |
| `weather:{city}` | `src/services/weather.py` | 1800 秒 | 和风天气结果 |
| `attractions:{city}:{limit}` | `src/services/map.py` | 86400 秒 | 高德景点列表 |

缓存值通过 JSON 序列化保存。

## 4. 当前项目没有自定义 ORM 业务表

当前后端依赖中包含 `sqlalchemy`，但代码中没有发现 SQLAlchemy model、Alembic 迁移或手写业务表 DDL。用户画像、操作日志等业务数据目前主要通过 ChromaDB 向量集合保存；会话和行程状态通过 LangGraph checkpoint 保存。
