## 落实：隐患 A 修复（itinerary 偏好硬约束，已实施）
- 根因：`itinerary_agent` 只把整个 `preferences` dict 透传 + 一句模糊的“优先利用”，prompt 规则从不提 interests/pace/hotel_preference/local_transport 怎么落地 → 靠 LLM 自觉读 JSON。
- 约束限制：`fetched_attractions` 无 category 字段（仅 name/address/rating/price/image_url），interests 无法做代码层类别匹配校验 → 硬约束只能在 prompt 层；pace 在 `validator._validate_itinerary:202-207` 已有软 warning（relaxed>4 / intensive<3）。
- 改动：
  1. `src/utils/state_utils.py` 新增 5 个取值函数：`get_interests`/`get_hotel_preference`/`get_local_transport`/`get_intercity_transport`/`get_travelers_type`，与现有 `get_pace`/`get_budget_level` 风格一致。
  2. `src/agents/itinerary_agent.py` `_state_payload` 把 `pace`/`interests`/`hotel_preference`/`local_transport` 从 preferences dict 抽为**顶层字段**（类似 budget_agent 把 travelers/budget_level 抽顶层的做法），提升 LLM 可见性。
  3. `itinerary_agent` prompt 新增“偏好硬约束（必须遵守，不得遗漏）”规则块：pace 定每日 item 数量区间（intensive 5-7 / relaxed 3-4）；interests 按类别每日至少 1 个匹配景点；hotel_preference 住宿选址匹配等级；local_transport 市内交通必须落在列表内、不得主推未列出方式。
- 验证：AST OK；venv 导入 OK；取值函数单测 OK；payload 含 4 项顶层字段 OK；prompt 含全部硬约束关键词 OK；`pytest test_validator_interrupts.py` → 2 passed。
